## 一、出生日期、学历层次写入接口（2026-11-18 已被替代）

### 1.1 背景

学生端「个人中心 → 档案概览 → 基本资料」需要支持学生维护 `birthDate`（出生日期）和 `degreeType`（学历层次）。当前后端读接口已返回这两个字段，但没有任何写接口，导致：

- 前端无法保存，只能展示；
- 后端完整度计算中「学业成绩」维度包含这两项，但全系统无写入入口，完整度固定封顶 87.5%（学业 8 项中 2 项不可写：6/8 × 0.5 × 100 = 37.5，加竞赛 30 + 综合素质 20）。

### 1.2 建议接口

```http
PUT /api/v1/profile/academic-info
Authorization: Bearer <student-token>
Content-Type: application/json; charset=utf-8
```

- 权限：学生本人（token 中的 userId），不允许修改他人。
- 语义：部分更新，只更新请求体中出现的字段。

### 1.3 请求体

```json
{
  "birthDate": "2003-05-20",
  "degreeType": "本科"
}
```

字段语义：

| 字段 | 类型 | 必填 | 语义 |
| --- | --- | --- | --- |
| `birthDate` | string | 否 | `YYYY-MM-DD`。字段**省略** = 不修改；传**空字符串** = 清空 |
| `degreeType` | string | 否 | 学历层次。字段省略 = 不修改；空字符串 = 清空 |

补充（当前前端行为，需后端确认取值协议）：

- 前端目前**没有可用的学历字典接口**，`degreeType` 以用户输入的文本原样提交（例如“本科”）。
- 若后端要求提交编码（例如 `1`）而非文本，请提供字典查询接口（建议 `GET /api/v1/common/dict?dictType=degree_type`），前端改为下拉并按编码提交。接口未提供前，按文本提交即可。

### 1.4 校验规则（建议）

| 字段 | 规则 | 失败返回 |
| --- | --- | --- |
| `birthDate` | 格式 `YYYY-MM-DD`；必须是合法日期；不得晚于当天 | 400 |
| `degreeType` | 长度 ≤ 20；需要在学历字典范围内（若后端有字典） | 400 |
| 两个字段同时省略 | 视为空更新，返回 400 或 200 且不落库（二选一，需在接口文档中明确） | — |

### 1.5 期望响应

成功（HTTP 200）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "birthDate": "2003-05-20",
    "degreeType": "本科",
    "degreeTypeLabel": "本科"
  },
  "trace_id": "req-...",
  "timestamp": "2026-11-17T18:00:00+08:00"
}
```

失败示例（HTTP 400）：

```json
{
  "code": 10001,
  "message": "出生日期格式不正确，应为 YYYY-MM-DD",
  "data": null,
  "trace_id": "req-...",
  "timestamp": "2026-11-17T18:00:00+08:00"
}
```

### 1.6 错误码（建议）

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | 10001 | 参数校验失败（日期格式、学历越界等） |
| 401 | 20003 | token 无效或过期 |
| 403 | 20004 | 越权修改他人信息（若实现） |
| 404 | 30001 | 接口不存在（当前未实现时的实际返回，见 1.8） |

### 1.7 验收标准

1. 调用成功后，`GET /api/v1/profile/info` 的 `data.academicInfo.birthDate` / `degreeType` / `degreeTypeLabel` 返回新值。
2. 触发一次评分重算后，`GET /api/v1/profile/data-completeness` 的 `academic.missingItems` 不再包含「出生日期」「学历层次」。
3. 非法日期、越界学历返回 400 且不落库。
4. 空字符串能清空对应字段；若产品不允许清空，请改为 400 并在文档中说明。
5. 只传 `birthDate` 时，`degreeType` 保持原值不变。

### 1.8 前端接入现状（2026-11-18 更正）

> **更正说明：** 本节原文声称「`updateAcademicInfo` 已实现、前端无需改界面」，与仓库实际不符——此前前端并不存在 `updateAcademicInfo`，也没有出生日期/学历层次的编辑控件。以下为当前真实状态。

- API 封装：`src/shared/api/student.ts` 新增 `updateBirthDate`（`PUT /profile/birth-date`），请求体 `{ birthDate }`；原 `updatePoliticalStatus`、`updateStudentStatus` 已删除。
- 页面：`src/features/profile/BasicInfoCard.vue`
  - 出生日期：`el-date-picker`，格式 `YYYY-MM-DD`，禁止选择未来日期，不可清空；
  - 学历层次：只读展示 `degreeTypeLabel`，注明「由管理员维护」，无编辑入口；
  - 政治面貌、学生状态：只读展示，编辑表单已移除对应控件；
  - 保存时先提交 `PUT /profile/contact`，出生日期有改动再单独提交 `PUT /profile/birth-date`；任一失败保持编辑态，并跳过「已保存」提示。
- 管理端：`src/features/teacher/org/StudentAccount.vue`「编辑账号」弹窗新增出生日期/学历层次/政治面貌/学生状态，异步加载详情后回填，仅提交变更字段。

## 二、错误码 30001 拆分的建议

### 2.1 两条实测对照

#### 对照 A：路由不存在

请求：

```http
GET /api/v1/profile/infos
Authorization: Bearer <student-token>
```

实际响应：HTTP **404**

```json
{"code":30001,"message":"请求的接口不存在"}
```

#### 对照 B：业务上的“邮箱未注册”

请求：

```http
POST /api/v1/auth/password/reset
Content-Type: application/json

{"email":"<未注册邮箱>"}
```

实际响应：HTTP **404**

```json
{"code":30001,"message":"该邮箱未注册"}
```

### 2.2 问题

两种完全不同性质的情况使用了同一个错误码 `30001`，且均返回 HTTP 404：

- 路由不存在属于**接口/部署层面**的错误，调用方无法通过改参数解决；
- 邮箱未注册属于**业务校验**结果，调用方可以引导用户更换邮箱或注册。

前端/第三方无法仅凭 `code` 区分，只能解析 `message` 文案，而文案可能随多语言或措辞调整而变化。

### 2.3 建议

1. **保留** `30001` 表示“请求的接口不存在”（HTTP 404），语义不变。
2. 为业务性“账号/邮箱不存在”分配独立业务码，例如：
   - `40001`：邮箱未注册
   - `40002`：手机号未注册
   - `40003`：账号不存在
   - HTTP 状态码建议用 **400 或 404 之一并固定**（当前为 404；若改为 400，请同步更新前端与文档）。
3. `message` 仍可保留中文提示，但前端判断逻辑应基于 `code`，不再解析文案。

### 2.4 兼容性与验收

1. `GET /api/v1/profile/infos` 仍返回 `{"code":30001,"message":"请求的接口不存在"}`。
2. `POST /api/v1/auth/password/reset`（未注册邮箱）返回新的业务码（如 `40001`），`message` 可保持“该邮箱未注册”。
3. 前端仅需在“忘记密码”流程中区分新业务码，其它 30001 处理逻辑不受影响。
4. 变更需在接口文档的“错误码表”中登记，并注明生效版本。
