### 记录 9：新增表

| 项目 | 内容 |
|------|------|
| 修改日期 | 2026-09-01 |
| 修改人 | lzw |
| 变更类型 | 新增表 |
| 变更字段 | `ai_message_feedbacks` |
| 变更原因 | 学生端 AI 对话消息反馈接口 `POST /ai/messages/{messageId}/feedback` 需记录学生对 AI 回答的有用/无用反馈（`user_id` / `message_id` / `feedback`），与教师端 `ai_teacher_feedbacks` 分离，通过 Flyway V34 迁移建表 |

**SQL 语句：**
```sql
CREATE TABLE `ai_message_feedbacks` (
    `id`               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `user_id`          BIGINT UNSIGNED NOT NULL COMMENT '反馈学生 ID',
    `message_id`       BIGINT UNSIGNED NOT NULL COMMENT '关联 ai_messages.id',
    `feedback`         VARCHAR(20)     NOT NULL COMMENT 'useful=有用 useless=无用',
    `created_at`       TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`       TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted_at`       TIMESTAMP       NULL DEFAULT NULL COMMENT '软删除时间',
    `is_deleted_null`  TINYINT(1)      GENERATED ALWAYS AS (IF(`deleted_at` IS NULL, 0, NULL)) STORED NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_aimf_user_message` (`user_id`, `message_id`, `is_deleted_null`),
    INDEX `idx_aimf_message_id` (`message_id`),
    CONSTRAINT `fk_aimf_user_id` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`),
    CONSTRAINT `fk_aimf_message_id` FOREIGN KEY (`message_id`) REFERENCES `ai_messages` (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='AI 消息反馈表（学生端）';
```

**回滚 SQL：**
```sql
DROP TABLE IF EXISTS `ai_message_feedbacks`;
```

| 修改人 | fmy |
| 变更类型 | 字段修改 |
| 变更字段 | `portrait_evaluation_scores.change` |
| 变更原因 | 2026-10-08 问题清单 §1.5：无对比学期时 `change` 落库为 `0`，接口返回 `"+0"`，被读成「与上阶段持平」。代码改为写 `null` 以区分「无对比」与「真实持平」，但 V7 建表时该列为 `NOT NULL DEFAULT 0`，写入 `null` 被数据库拒绝（ERROR 1048）→ 通过 Flyway V38 迁移放开可空 |

**SQL 语句：**
```sql
ALTER TABLE `portrait_evaluation_scores`
    MODIFY COLUMN `change` DECIMAL(5,2) NULL DEFAULT NULL COMMENT '较上阶段变化；无对比学期时为 NULL';
```

**回滚 SQL：**
```sql
-- 回滚前需先把既有的 NULL 值填回 0，否则新的 NOT NULL 约束会失败
UPDATE `portrait_evaluation_scores` SET `change` = 0 WHERE `change` IS NULL;
ALTER TABLE `portrait_evaluation_scores`
    MODIFY COLUMN `change` DECIMAL(5,2) NOT NULL DEFAULT 0 COMMENT '较上阶段变化';
```

> 语义约定：`change IS NULL` ⇔ `compared_semester_id IS NULL` ⇔ 无对比学期；`change = 0.00` ⇔ 真实持平。

| 变更原因 | 2026-10-08 问题清单 §1.1 / §1.2 / §1.5 的存量数据问题（详见脚本内注释） |
| 执行方式 | **根目录独立脚本 `repair_2026-10-08_issues.sql`**，幂等、可重复执行、带事务与回滚段 |

> ⚠️ **为什么不做成 Flyway 迁移**：这些是**存量业务数据**修复，写成迁移会在所有环境（含生产）自动执行，
> 风险不可控；且已应用的迁移文件受校验和约束不得改写。沿用 `repair_political_status.sql` 的既有做法，
> 由运维/开发按环境手动执行。**新增 schema 变更仍走新的 V{n} 迁移**（见记录 10）。

**关键语句（节选，完整脚本见 `repair_2026-10-08_issues.sql`）：**
```sql
-- §1.1 保留 id=60（社会实践），把 id=53 改造为「绩点达标」（权重不动，前端零改动）
UPDATE `evaluation_indicators`
SET `indicator_name` = '绩点达标',
    `description`   = '学分加权绩点 Σ(gpa×credit)/Σ(credit) 达到 3.0 及以上得 100 分，未达标得 0 分',
    `scoring_rule`  = CAST('{"type":"THRESHOLD","source":"weighted_gpa","threshold":3.0,"score":100}' AS JSON),
    `updated_at`    = NOW()
WHERE `id` = 53 AND `deleted_at` IS NULL AND `indicator_name` = '志愿时长达标';

-- §1.2 当前学期按学期名认定；脏学期及其连带记录一并软删（可回滚）
UPDATE `semesters`
SET `is_current` = CASE WHEN `name` = '2025-2026-2' THEN 1 ELSE 0 END
WHERE `deleted_at` IS NULL
  AND COALESCE(`is_current`, -1) <> CASE WHEN `name` = '2025-2026-2' THEN 1 ELSE 0 END;

-- §1.5 清掉历史的脏 0（无对比学期却落了 0）
UPDATE `portrait_evaluation_scores`
SET `change` = NULL
WHERE `compared_semester_id` IS NULL AND `change` IS NOT NULL;
```

**回滚 SQL：** 见脚本第 6 节（字段级回滚）与第 3 节后的注释（软删回滚）。

> **执行后必须人工完成的两步**（脚本不会自动执行，见脚本第 5 节）：
> 1. **重新发布指标规则版本**（`POST /admin/indicators/publish`，**不传 `sourceVersionId`**）——
>    评分引擎读的是发布时冻结的 `indicator_rule_versions.tree_snapshot`，只改活表不重发，§1.1 的改造**不会**影响评分。
> 2. **触发一次评分重算**（`POST /admin/scores/recalculate`），使 §1.1 / §1.5 反映到评分结果。
